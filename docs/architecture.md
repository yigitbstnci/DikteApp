# Dikte Architecture

This document is the stable architecture map for agents and maintainers. Keep it high signal and update it when implementation facts change.

## Runtime Shape

Dikte is a native macOS menu bar application for context-aware dictation. The app records microphone audio, monitors clipboard changes during the recording, transcribes speech locally with WhisperKit, merges transcript text with copied context, and writes Markdown output back to the system clipboard.

Core workflow:

1. The user toggles recording with `Command + Shift + Space`.
2. `AudioRecorderService` captures microphone input to a temporary WAV file.
3. `ClipboardMonitorService` polls `NSPasteboard.general.changeCount` while recording.
4. `TranscriptionService` transcribes locally with WhisperKit.
5. `MergerService` injects clipboard markers into transcript text by timestamp.
6. `AppState` copies the final Markdown output to the system clipboard.

- `AGENTS.md` contains operating rules for coding agents.
- `docs/architecture.md` is the maintained architecture reference.
- `docs/current-state.md` is the first context file agents should read for live project status.
- `docs/context/index.yml` is the structured index used by repo-level context scripts.

## Key Code Areas

- `Sources/DikteApp.swift`: application entry point, menu bar scene, settings scene, app delegate, and HUD manager wiring.
- `Sources/AppState.swift`: central coordinator for recording, processing, transcription, merging, and clipboard output.
- `Sources/Models/RecordingSession.swift`: transcript segment and session models.
- `Sources/Models/ClipboardItem.swift`: clipboard item model and attachment-line formatting.
- `Sources/Services/AudioRecorderService.swift`: microphone capture through `AVAudioEngine`.
- `Sources/Services/ClipboardMonitorService.swift`: pasteboard polling, source app detection, and clipboard artifact persistence.
- `Sources/Services/TranscriptionService.swift`: WhisperKit model loading, transcription, and transcript cleanup.
- `Sources/Services/MergerService.swift`: timestamp-based merge algorithm.
- `Sources/Views/`: SwiftUI menu bar, HUD, onboarding, settings, and design system views.

## Core Service Details

### Audio Recording

- `AudioRecorderService` uses `AVAudioEngine` and `AVAudioFile`.
- Audio is written as a temporary `.wav` file in `FileManager.default.temporaryDirectory`.
- `recordingStartTime` is captured when the engine starts and anchors clipboard timestamp alignment.
- Recording metrics track frame count, RMS, and peak so empty or very low signal recordings can fail early.

### Clipboard Monitoring

- `ClipboardMonitorService` polls `NSPasteboard.general.changeCount` every `0.3` seconds while recording.
- Text, URLs, and images are persisted under `~/Library/Application Support/Dikte/ClipboardAssets`.
- Text and URLs are saved as `.txt`; images are read as `NSImage`, converted to PNG, and saved as `.png`.
- Terminal apps can mutate pasteboard-like state on selection, so text from terminal-like apps is held pending and only captured when the same content is confirmed shortly after. Images stay immediate.
- Each `ClipboardItem` stores absolute timestamp, source app, file path, size, type, and relative time.

### Transcription

- `TranscriptionService` uses WhisperKit with `openai_whisper-large-v3_turbo`.
- Models are cached under `~/Library/Application Support/Dikte/Models`.
- Audio is normalized to 16kHz mono before transcription using `AVAudioConverter`; normalization is skipped if audio is already compatible.
- The primary decode path uses Turkish (`language: "tr"`) with word timestamps enabled when clipboard items are present.
- If no usable segments are returned, transcription retries in fallback mode without word timestamps.
- Transcript cleanup removes Whisper special tokens and known recurring hallucination phrases before merging.
- Hallucination cleanup is context-aware: only trailing hallucinations are removed, not mid-sentence occurrences.

### Merge Output

- `MergerService` sorts clipboard items by relative timestamp and merges them into transcript pieces.
- Word timestamps are preferred when available; otherwise segment-level timings are used.
- Clipboard references are inserted as Unicode superscript markers.
- The final output includes an `Attachments` section with numbered file or URL references.

### Logging

- `DikteLog` writes compact terminal/file log lines with time, short level code, `area.event`, message, and sorted `key=value` metadata.
- A short per-recording session ID is created in `AppState` and passed through audio recording, clipboard monitoring, transcription, merge, and output-copy logs.
- Logs include diagnostic metadata such as durations, counts, byte sizes, source app names, device identifiers, model/cache state, and audio signal metrics.
- Logs must not include raw transcript text or copied clipboard text; content is represented by counts, type, source, and persisted artifact metadata.

### Permissions And Entitlements

- `Resources/Info.plist` declares `NSMicrophoneUsageDescription`.
- `Resources/Dikte.entitlements` enables audio input.
- App sandbox is set to false so the app can read global pasteboard contents from other apps.

## Runtime Storage

- Whisper models: `~/Library/Application Support/Dikte/Models`
- Clipboard assets: `~/Library/Application Support/Dikte/ClipboardAssets`
- Structured app logs: `~/Library/Logs/Dikte/dikte.log`
- Derived build app path marker: `.build/dikte-app-path`

## Build And Debug Flow

Use the Makefile for local work:

```bash
make run
make test
make stop
```

`make run` regenerates the Xcode project, builds the Debug app, stops any running Dikte process, launches the built `.app` through LaunchServices, tails the structured log file, and ends the terminal stream when the Dikte process exits.

## Context System

The repo-resident context system is intentionally separate from the Swift app runtime. It provides agent continuity through committed Markdown and simple shell scripts:

- `make context-load` prints bounded startup context.
- `make context-save SUMMARY=/path/to/session.md TITLE="short-title"` stores a session summary and updates the index.
- `make context-check` validates the context docs and index.

Session summaries are deliberately coarse-grained: use them for meaningful development blocks or daily summaries, not every runtime recording, log session, or small debugging attempt. Runtime diagnostic IDs and raw logs stay in `~/Library/Logs/Dikte/dikte.log`; committed context keeps distilled facts, decisions, verification, and follow-ups.

Agent-specific hooks may call these commands, but the committed Markdown files remain the durable source of truth.
